# Regulars

A Godot 4.7 restaurant-survival game: cook meat, serve named townsfolk, earn money, survive
as many days as possible. Working title; the current build is a vertical slice.

## Run and test

```bash
/Applications/Godot.app/Contents/MacOS/Godot --path .                      # play
/Applications/Godot.app/Contents/MacOS/Godot --headless --import           # fresh checkout/worktree, or after adding assets or a new `class_name`
/Applications/Godot.app/Contents/MacOS/Godot --headless -s addons/gut/gut_cmdln.gd   # tests (GUT 9.7.1)
```

- Run `--headless --import` first in any fresh checkout: the `.godot` cache is not in git, and
  without it scripts fail to load and screenshot runs hang.
- All tests should pass before and after a change (about 45 s).
- Screenshot a visual change:
  `REGULARS_SHOT=/abs/path.png REGULARS_SHOT_AT=13.5 REGULARS_DEMO=cook godot --path .`
  Add `REGULARS_THEME=seaside` for the second theme, `REGULARS_INPUT=touch|pad` for touch or
  controller hints. The list of demos and their shoot times is in `_apply_demo` in
  `game/main/demos.gd` (set-ups in `game/main/demo_scenes.gd`). Run only the demos your change touches.

## Layout

| Where | What | Start with |
|---|---|---|
| `sim/` | Pure game logic, no scene dependencies, unit-tested. Keep it that way. | `menu.gd` (the player's menu), `kitchen.gd`, `ledger.gd`, `town.gd`, `staff.gd`, `floor_mess.gd` |
| `game/` | The scene layer. | `main.gd` (`class_name Game`) |
| `game/main/` | What `Game` does, one object per topic, called `game.<part>.<func>()`. | `serving.gd`, `cooking.gd`, `day.gd`, `placing.gd` |
| `game/hud/`, `game/hud.gd` | Interface parts, `game.hud.<part>.<func>()`. | `day_ui.gd`, `shop_ui.gd` |
| `game/build/`, `game/build.gd` | Visuals generated in code (palette, shapes, food, stations). | `food.gd` (`BuildFood`) |
| `game/crew/`, `game/crew.gd` | Hired helpers in service. | `task_run.gd` |
| `game/desk/`, `game/desk_screen.gd` | The staff desk. | `posting.gd` |
| `test/unit/` | GUT tests, one file per topic. `test_game_*.gd` drive the real scene. | `test/helpers/game_case.gd` (base for scene tests) |
| `assets/` | `sfx/` generated by `tools/make_sfx.py`; `music/` mapped in `MUSIC` in `game/main.gd`. | |
| `docs/` | `DESIGN.md` (built/parked), `STYLE_GUIDE.md` (art source of truth), `AUDIO_GUIDE.md`, `ART_BRIEF.md`. | `docs/STYLE_GUIDE.md` |
| `tools/` | `gdsplit.py` moves functions between files; `split_tests.py` splits a test file. | Read their docstrings first |

## Finding and changing code

- Find a function by name before opening anything: `grep -rn "func serve\b" game sim`.
  Each part file opens with a comment on what it holds; no file needs a whole read.
- All shared state (every `var`) lives on `Game` in `game/main.gd`. State only one part uses can
  be a `var` on that part. Each chef's own state is on `Player` (`game/player.gd`).
- Put new code in the part that owns the topic. A new part is a file with `class_name GameX`,
  `extends RefCounted`, `var game: Game`, `func _init(game_: Game)`, plus a
  `var x := GameX.new(self)` line in `main.gd`.
- Keep files under about 800 lines; split one past 1,000.
- Parts type their owner (`game: Game`), so a bad reference fails at compile time (`Parse Error`
  in the test run). Other scripts and tests hold `game` untyped, so after moving or renaming a
  function, grep for `\.name\b` across `game/` and `test/` and run the tests and affected demos.
- A part is a `RefCounted`, not a node: a deferred call or timer bound to its method can outlive
  the scene. Guard with `is_instance_valid(game)` or bind to the node.
- New tests of the game scene extend `res://test/helpers/game_case.gd`. GUT reads only `test/unit/`.

## Art

- Follow `docs/STYLE_GUIDE.md` (its "Resolved conflicts" and "Rules so far" win over concept
  images in `docs/art/`, which contain mistakes). Note any departure in its "As built" section.
  Grep it by line range; it is about 1,100 lines.
- Camera is fixed: orthographic, 37 degrees down, rotated 45 degrees. Characters must read at
  about 60 px, food and icons at about 20 px.
- Do not change gameplay rules to match a picture; ask first.
- Decided: peg-doll logo, name "Regulars". Open, so do not pick: title screen, colour-blind
  support, the "Town Diner" subtitle.
